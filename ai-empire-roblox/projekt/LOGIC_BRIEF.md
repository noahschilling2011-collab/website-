## 2. Decisions already made by the user (do not re-ask)
- Day length stays 20 real minutes (15 min day 08–18, 5 min night) — EmployeeConfig.hour.
- Control: ALMOST EVERYTHING AUTOMATIC. The company runs itself (HR plans vacation/shifts, sales find and close customers, field staff travel, hotel is billed automatically). The player watches, expands (buys/upgrades/hires/trains/releases) and can optionally step in.
- Money: income is too low AT THE START (first minutes up to the first model / first employees) — fix the early game first, without making the late game explode.
- Company cars: only FIELD STAFF + the BOSS get company cars (not every employee).
- The company starts VERY SMALL (see request 13).

## 3. Hard constraints
- Deliverable: ONE Roblox place file (.rbxlx) packed by ROOT/pack.py from ROOT/work/src. Everything must be testable in Studio from that one file (so: no multi-place teleport architecture as the core; a distant area inside the same place is fine).
- Never invent Roblox APIs (check ROOT/tools/API-Dump.json), asset ids, or Robux product/game-pass ids. Monetization reads ids from a config table that defaults to 0 = disabled (nothing shown) until the owner fills in ids he created on create.roblox.com. Respect Roblox rules (paid random items need odds + PolicyService; no gambling).
- Old saves must load and keep their progress; new fields via EmpireMath.new defaults + Template.migrate cleaners (+ DATA_VERSION bump only if a transform is needed). Staff profile fields must be added to cleanProfile, profilesConsistent, SessionService.profileSignature, StaffAssignment.profile, Rig.Profile together (or stored in a separate map keyed by stable id).
- Performance: tier-4 plot already ≈ 20,900 building parts + 4,700 rig parts, 12 plots/server; NPC pathfinding has 2 concurrent path jobs server-wide; snapshot bandwidth today is ~100–214 KB per snapshot at up to 4/s (MUST be reduced: split/omit unchanged heavy fields, lower rate). Shared world additions (city, airport, abroad) are built ONCE per server and stream.
- Honest: dialogue is authored (no AI backend); every number shown comes from real game state; tests reported as passed/failed/not run.
- Keep everything that works today (lift, doors, recruiting/interviews, assistant, screens, building generators, existing apps) working; UI language English; `--!strict` style of the surrounding code.

## 4. Known root causes (from the analyses) the design MUST address
- Income collapse: NPC rivals improve without cap and pay no wages → player share → 0 within ~45 min (economy.md). Refinement compounds without cap (AIModelService:209/409). Hiring fees dominate staff cost. Only one scalable income source (consumer subscriptions). Office 2 is never reached by a casual player.
- Staff output is cosmetic: which task an employee does has no effect; offscreen staff count 100% around the clock, watched staff less (time_staff.md, staff_life.md). Ops staff (reception, chef, barista, security …) are unpaid, never eat, leave posts for coffee.
- Several live models: allowed, but identical clones stack (+70 % each) — exploit; one training slot; refinement takes a model offline; no ageing (models.md).
- Customers: five disconnected systems, once-a-day clicks; B2B leases race to the bottom; no staff/time/travel involved (contracts_customers.md).
- Three disagreeing clocks (1200 s day, 3600 s "game month", real UTC day). Company clock not saved; Lighting global per server.
- live table replaced every second wipes live.workforce/live.admin (data_ui.md / time_staff.md).

## 5. Design targets (to be refined by the design phase, verified by simulation)
- First 10 minutes: the player has a clear first goal and ≥ $1–3k/min income by minute 5–10; office 2 reachable at ~25–40 min for a casual player, office 3 at ~70–100 min, office 4 at ~2.5–3.5 h; no collapse and no runaway (income stays bounded and grows with the company, wages 25–45 % of revenue in the mid game so staff decisions matter).
- Every department/room of the building has a visible, measurable job; bigger office = more capacity and new revenue streams.
- One calendar: game day = 1200 s; vacation, hotel nights, trips, payroll and retainers counted in game days; saved per player (based on persisted play time) while the world day/night is the server clock.
